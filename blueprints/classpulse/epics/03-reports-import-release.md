## Conventions that bite in this area

- **CSV cell rules (all exports):** a PHP `null` cell ⇒ empty (nothing between commas); `int` ⇒ its digits,
  unquoted; `string` ⇒ sanitised (prefix `'` when it starts with `=`, `+`, `-`, `@`, tab or CR), embedded `"`
  doubled, wrapped in `"`; cells joined with `,`; every line ends with `\n` (LF), including the last; no BOM. Averages
  are strings (`"2.67"`, `"No data"`). Absent day cells are the string `"A"`.
- **`student_number` is always a text cell.** In all three exports (weekly, semester, student) a null
  `student_number` is written as `""` (an empty quoted text cell), exactly as `tests/Fixtures/weekly-export.csv`
  shows — pass `$student->student_number ?? ''` to `CsvWriter::line`, never the raw null. The weekly and semester
  exports have a `Student number` column; the student export has no such column, so the rule never fires there, and if
  one is ever added it follows the same rule. Only day cells and point cells use the empty (unquoted) null.
- **Export filenames:** `classpulse-<kind>-<class slug>-<period>-exported-<today>.csv`, where the slug is the name with
  every run of characters outside `A-Za-z0-9` replaced by `-` and trimmed of `-` (`HNL 2O` ⇒ `HNL-2O`). Weekly period
  = the Monday date; semester and student period = `<from>-to-<to>`; the student kind adds the student-name slug after
  the class slug (`Alex Rivera` ⇒ `Alex-Rivera`).
- **Roster order** everywhere: `strcmp(mb_strtolower(display_name))`, ties by `id`.
- **Links to a page from a later step use `url()`, never `route()`** (`/students/<id>` from the semester table arrives
  in E3-T3).
- **Release scripts run on the macOS host** and call Docker for PHP, Composer and MariaDB; they need `rsync`, `zip`,
  `unzip` and `sed` from the host. They must never touch other containers.
- **Owner docs are Spanish**, code comments English, UI strings English.
- **Every test file names the method its step's gate lists** (`vendor/bin/phpunit --list-tests <file> | grep -q
  '<Class>::<method>'`).

Full project rules: `CLAUDE.md`. Area rules: `.claude/rules/frontend.md`, `.claude/rules/security.md`,
`.claude/rules/calculations.md`. They sit in the project root — the builder copied them there from the bundle's

### `E3-T4` — Add the roster import service with preview and commit

**Depends on:** `E3-T3` · **Priority:** p1

`RosterImporter::preview()` validates with `Validator::make(...)->validate()`: exactly one of `file`
(file|max:256|extensions:csv,txt) or `pasted` (string|max:262144); strips a UTF-8 BOM; detects the delimiter from the
first line by the highest count of `,`, `;` or tab (default `,`); recognises headers case-insensitively: `name`, or
`first_name` + `last_name` (joined with one space), optional `student_number`; a file with no recognised header and
pasted text treat every non-empty line's first cell as the name. Each row gets `row` (1-based data row number),
`name` (trimmed, whitespace collapsed), `student_number`, `status` and `reason`: `ERROR` for an empty name
(`Name is empty.`), a name over 120 characters (`Name is longer than 120 characters.`), or an `OK` row beyond
`remainingCapacity()` (`Roster cap reached.`); `WARNING` when the normalized name (`mb_strtolower` of the collapsed
name) or a non-empty `student_number` matches an existing student of the class (`Matches an existing student.`) or an
earlier row (`Repeats row N.`); otherwise `OK`. The rows are stored in the session under
`classpulse.import.<token>` (token `Str::random(40)`) with the class id, and `preview()` returns `token` and `rows`.
`commit()` re-reads the stored rows (unknown token or another class ⇒ `ValidationException` on `token`), ignores
`ERROR` rows, re-checks capacity inside `DB::transaction` with the class row locked (selected valid rows > remaining ⇒
`ValidationException` on `roster_cap`, 0 created) and creates the selected students; it returns the number created.
Never merge names automatically. `tests/Feature/RosterImporterTest.php` calls the service directly (session store
available in Feature tests; files via `UploadedFile::fake()->createWithContent()`), and has a method named
`test_bom_semicolon_file_previews_joined_names_as_ok`.

**Files**
- `app/Services/RosterImporter.php` — new
- `tests/Feature/RosterImporterTest.php` — new

**Acceptance**

1. **WHEN** `RosterImporter::preview()` receives a UTF-8 file with a BOM, the `;` delimiter and the header `first_name;last_name;student_number` **THE SYSTEM SHALL** return every row with the joined name, its student number and status `OK`.
2. **WHEN** a row matches an existing student of that class by normalized name or by `student_number`, or repeats an earlier row **THE SYSTEM SHALL** mark it `WARNING`.
3. **WHEN** a row has an empty name, a name longer than 120 characters, or would exceed the class roster cap **THE SYSTEM SHALL** mark it `ERROR`.
4. **WHEN** `RosterImporter::commit()` receives the preview token and selected row numbers **THE SYSTEM SHALL** create exactly the selected `OK` and `WARNING` rows in one transaction and never an `ERROR` row, and an unknown token SHALL raise a `ValidationException` and create 0 students.
5. **WHEN** pasted names, one per line, are previewed **THE SYSTEM SHALL** treat each non-empty line as one row, and a file over 256 KB or with an extension other than `.csv` or `.txt` SHALL raise a `ValidationException`.
6. **WHEN** the roster cap is reached between preview and commit **THE SYSTEM SHALL** create 0 students and raise a `ValidationException` on the key `roster_cap`.
